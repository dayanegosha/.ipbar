# .ipbar

локальный IP прямо в строке меню macOS.

```text
192.168.1.105
```

нажал на адрес — получил интерфейс, маску, шлюз, DNS, MAC и IPv6. нажал на значение — скопировал. никаких аккаунтов, серверов и внешних сервисов определения IP.

SwiftUI и AppKit. macOS 14+, Apple Silicon и Intel. без сторонних библиотек и иконки в Dock.

## установка

скачай `ipbar-macOS.zip` из [релизов](https://github.com/dayanegosha/.ipbar/releases/latest), распакуй и перенеси **ipbar.app** в «Программы». запусти приложение — текущий адрес появится в строке меню. обычного главного окна нет.

готовая сборка подписана ad-hoc и не нотарифицирована Apple. если macOS блокирует первый запуск, используй подтверждение в «Настройки системы → Конфиденциальность и безопасность». [инструкция Apple](https://support.apple.com/ru-ru/102445). отключать Gatekeeper не нужно.

## возможности

- автоматический выбор интерфейса по default route; поддержка Wi-Fi, Ethernet и VPN, включая полный туннель через пару маршрутов `/1`;
- реальные IPv4, дополнительные адреса, маски, IPv6, MAC, шлюз и доступные DNS-серверы;
- копирование каждого адреса и MAC нажатием, полный текстовый отчёт через **Copy All**;
- постоянные обновления по системным сетевым событиям; дополнительный опрос с интервалом 1, 3, 5, 10 или 30 секунд;
- выбор Wi-Fi, Ethernet, VPN или конкретного обнаруженного интерфейса;
- IPv4 или IPv6 в строке меню; у IPv6 предпочитается глобальный адрес, затем ULA и link-local со scope-id;
- три формата строки меню: адрес, адрес с интерфейсом, `IP: адрес`;
- меню без прокрутки, дополнительные адреса — на отдельной странице с перелистыванием;
- настройки на вкладках внутри popover, без отдельного окна;
- переключатель питания Wi-Fi и переход к подключению, паролям и Personal Hotspot в системных настройках;
- первый запуск с предложением скрыть лишний значок Wi-Fi; эта же подсказка доступна в настройках;
- сохранение настроек и включённый при первом запуске автозапуск через SMAppService.

без IPv4 отображается `No IP`, без выбранного IPv6 — `No IPv6`. при обновлении новый снимок заменяет предыдущий целиком, без промежуточного No IP. ширина элемента соответствует тексту со стандартными отступами macOS. если чтение затягивается больше двух секунд, старый адрес убирается с предупреждением. отключённый вручную выбранный интерфейс не подменяется адресом другого адаптера.

при первом запуске приложение регистрирует запуск при входе. если macOS требует подтверждение или возвращает ошибку, это видно рядом с переключателем. после ручного отключения приложение не включает автозапуск снова.

значок Wi-Fi скрывается самим пользователем в системных настройках. приложение открывает нужную страницу и не меняет системные предпочтения скрытым способом. кнопка подключения открывает штатный список сетей: приложение не хранит пароли Wi-Fi.

пункт **Automatically refresh** управляет дополнительным опросом. системные уведомления продолжают работать и при выключенном опросе. это сохраняет актуальность адреса без постоянного таймера.

## особенности сети

`Connected` означает, что локальный интерфейс имеет IPv4 и системный маршрут или шлюз. это **не проверка доступности интернета**: приложение не выполняет внешних запросов. самоназначенный `169.254.x.x` получает отдельный статус.

в режиме IPv6 Automatic использует системный основной IPv6-интерфейс. полный адрес может занимать больше места в строке меню. по умолчанию выбран IPv4.

для split-tunnel VPN единого «VPN-адреса для всего трафика» нет: Automatic показывает интерфейс default route, а VPN можно выбрать вручную. per-app VPN и маршрутизация по отдельным назначениям не сводятся к одному адресу.

macOS может скрывать SSID без доступа к геолокации. приложение использует CoreWLAN, показывает имя, когда оно доступно, и объясняет отсутствие данных. разрешение на геолокацию не запрашивается; основной функционал в нём не нуждается.

DNS берётся из SystemConfiguration. при использовании глобального набора есть пометка `system default`. доменные/scoped resolver-правила могут отличаться; это не полный аналог `scutil --dns`. у виртуального туннеля может не быть MAC или обычного шлюза — такие поля показываются как `Unavailable`.

## сборка

нужны Xcode 15+ с Command Line Tools и macOS 14+. сторонние зависимости не устанавливаются.

```sh
git clone https://github.com/dayanegosha/.ipbar.git
cd .ipbar
open IPBar.xcodeproj
```

выбери схему **IPBar** и нажми Run. проект использует локальную ad-hoc подпись и не требует Apple Developer Team.

универсальная release-сборка через `xcodebuild`:

```sh
./scripts/build-app.sh
```

результат: `dist/ipbar.app` и `dist/ipbar-macOS.zip`, оба с `arm64` и `x86_64`. скрипт собирает во временном каталоге, проверяет архитектуры и подпись. для распространения используй ZIP: облачная синхронизация папки с `.app` может дописать расширенные атрибуты и повредить проверку подписи.

для собственной Developer ID подписи передай `CODE_SIGN_IDENTITY` скрипту. нотарификация — отдельный шаг владельца сертификата; скрипт не выдаёт ad-hoc подпись за Developer ID.

тесты:

```sh
./scripts/test.sh
```

диагностика без запуска интерфейса:

```sh
'dist/ipbar.app/Contents/MacOS/ipbar' --diagnostics
```

команда выводит JSON с реальными сетевыми параметрами этого Mac. не публикуй его без проверки: в нём могут быть внутренние адреса, MAC и SSID.

## устройство проекта

- `IPBar/Models` — снимок сети, выбор интерфейса, статусы и текстовый отчёт;
- `IPBar/Services` — чтение адресов и маршрутов, наблюдение за изменениями, настройки и автозапуск;
- `IPBar/Views` — нативные SwiftUI-представления меню и настроек;
- `IPBar/App` — жизненный цикл AppKit, NSStatusItem и NSPopover;
- `IPBarTests` — маршруты, отключение интерфейсов, смена адреса, сохранение настроек и гонки асинхронных обновлений.

сетевое ядро собирается в локальную статическую библиотеку `IPBarCore`, включённую в приложение. все изменения интерфейса выполняются на MainActor; чтение сети — на отдельной последовательной очереди.

подробнее: [архитектура и API](Docs/Architecture.md), [проверки и ограничения](Docs/Testing.md).
