# проверки и ограничения

## автоматические проверки

`./scripts/test.sh` запускает XCTest через `xcodebuild`, схема `IPBar`. временный DerivedData находится вне папок облачной синхронизации, чтобы посторонние Finder-атрибуты не ломали подпись тестового bundle.

26 тестов покрывают:

- приоритет основного интерфейса при одновременных Wi-Fi и Ethernet с нестандартными BSD-именами;
- IPv6-only интерфейс, отсутствие IPv4, link-local адрес и отключённый адаптер;
- ручной выбор пропавшего интерфейса без перехода на другой;
- unscoped/scoped default, полный VPN через `/1 + /1`, обычный split tunnel;
- бинарный парсер маршрутов, компактную маску, обрезанные и повреждённые записи;
- смену DHCP-адреса и переключение Ethernet → Wi-Fi на контролируемых снимках;
- содержимое Copy All и отключение IPv6 в отчёте;
- сохранение настроек в отдельном тестовом UserDefaults domain;
- отбрасывание результата после сетевого события или остановки монитора;
- событийное обновление изолированного монитора без периодического таймера;
- атомарную замену адреса без промежуточного No IP и непродлеваемый таймаут при потоке событий;
- выбор IPv6-интерфейса, предпочтение глобального IPv6 и сохранение scope-id link-local адреса.

тесты монитора используют управляемый источник данных и не меняют системную сеть. исходники NetworkMonitor и SettingsStore также компилируются в hostless test target, чтобы проверить реальную реализацию без запуска приложения и системных наблюдателей.

GitHub Actions запускает тесты на macOS 15 отдельно на Apple Silicon и Intel (`macos-15` и `macos-15-intel`). отдельный job собирает Universal `.app`, распаковывает дистрибутив, проверяет подпись и наличие `arm64`/`x86_64`.

## проверено локально

на Apple Silicon с Xcode 27.1 и macOS 27:

- сборка Debug и Release через `xcodebuild`, 26 тестов без ошибок;
- Universal Binary с минимальной версией macOS 14.0 для обеих архитектур;
- проверка подписи распакованного release-архива через `codesign --verify --strict --deep`;
- реальный IPv4 совпадает с `ipconfig getifaddr` основного интерфейса; интерфейс и шлюз совпадают с `route -n get default`;
- меню показывает полученные IPv4, маску, DNS, MAC, IPv6 и отсутствие доступного SSID;
- выбор неподключённого Ethernet показывает Offline / No IP, возврат к Automatic возвращает актуальный Wi-Fi-адрес;
- нажатие IPv4 и Copy All даёт подтверждение копирования;
- режим отображения сохраняется после перезапуска приложения;
- выпуск запускается обычным `.app`, без главного окна и запроса прав администратора;
- первый запуск новой версии показывает onboarding с включённым автозапуском, зарегистрированным через SMAppService;
- переходы из popover открывают реальные разделы Menu Bar и Wi-Fi в System Settings;
- настройки открываются внутри того же popover, а IPv6 выбирается и отображается по реальным данным Mac.

локальные диагностические данные не включены в репозиторий.

## границы проверки

физическое переключение кабеля Ethernet, смена DHCP-сервера, реальные сторонние VPN, IPv6-only сеть и запуск на физическом Intel Mac в этом окружении не проверялись. маршрутизация и отключения покрыты контролируемыми тестами; они не заменяют проверку конкретного сетевого оборудования или VPN-клиента.

переключатель питания Wi-Fi реализован через CoreWLAN, но системный Wi-Fi не отключался во время разработки, чтобы не прерывать рабочее подключение. реальный полный offline-сценарий требует отдельной проверки на тестовом Mac: выключить Wi-Fi и отсоединить Ethernet, проверить `No IP`, затем подключиться заново. выбор отсутствующего адаптера проверен в реальном интерфейсе приложения.

регистрация автозапуска через SMAppService проверена из пользовательской папки Applications. выход из пользовательского сеанса и повторный вход не выполнялись. для ручной проверки перенеси приложение в «Программы», включи Launch at login, подтверди запрос macOS при необходимости и войди в систему заново.

## ручная проверка перед распространением

1. запустить `.app`, сверить адрес в строке меню с системными настройками сети;
2. подключить Ethernet при активном Wi-Fi: Automatic должен следовать системному маршруту; затем отключить кабель;
3. получить новый DHCP lease или сменить Wi-Fi: старый адрес не должен возвращаться после обновления;
4. проверить full-tunnel и split-tunnel VPN; при split tunnel отдельно выбрать VPN в настройках;
5. выбрать интервал 30 секунд, сменить сеть и убедиться, что системное событие обновляет адрес раньше периодического опроса;
6. отключить все подключения, затем восстановить сеть; проверить IPv6-only и `169.254.x.x`;
7. проверить сон/пробуждение, Copy All, сохранение настроек и запуск при входе;
8. проверить тёмную и светлую темы, увеличенный системный текст и переполненную строку меню.

macOS самостоятельно скрывает status items, если места в строке меню не хватает. в этом случае закрой лишние элементы или выбери Address only; повторное открытие .ipbar открывает popover.

runner macOS 14 исключён из текущей матрицы из-за [завершения поддержки GitHub 2 ноября 2026 года](https://github.com/actions/runner-images/issues/13518). более ранняя версия прошла проверки на macOS 14; минимальная версия приложения остаётся 14.0. финальную версию нужно дополнительно проверить на macOS 14 перед развёртыванием в такой среде.
